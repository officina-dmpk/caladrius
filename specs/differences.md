# Documented differences

Places where Caladrius deliberately gives another answer than an oracle value (PKNCA, or later the reference software), or where two methods cannot reach the same number. A gap listed here is a decision, not a failure: it is never absorbed by widening a tolerance (`AGENTS.md` section 5).

## How a difference is recorded

1. An entry below, with an identifier `D-<number>`: what the oracle does, what Caladrius does, why, and which cases and parameters are affected.
2. In the options file of each affected oracle case (`oracle/expected/<case>.options.json`), a `documented_differences` array. Each element has `id` (the identifier above), `parameters` (PKNCA names), optionally `subjects` (a list of subject codes; absent means every subject of the case) and optionally a one-line `note`. The testkit refuses a file whose identifier is malformed or that names a subject or parameter the case does not have.
3. The effect: the testkit comparison (`compare_tables_documented`) leaves those values out and lists them in the report next to the failures; `cargo xtask conformance` counts them in their own column of `docs/conformance.md`, in neither the validated nor the expected totals. A documented value that Caladrius happens to reproduce is still not counted as validated. Moving a row from "validated" to "documented" lowers the validated floor and fails the run, so a difference cannot hide a regression; adding a new one is a deliberate edit of an options file plus an entry here.

Status tags are those of `specs/README.md`.

## D-01 Trailing negative concentration is never Tlast or Clast

- **What PKNCA 0.12.1 does.** With a negative concentration in the data it only warns and goes on. Tlast is the last point whose concentration is not zero, so a negative value at the end of the profile becomes Tlast and its value becomes Clast. The area to Tlast then runs up to that point, and every quantity built on Tlast, Clast or the area to Tlast follows: the extrapolation to infinity, the percentages, clearance, volume and mean residence time. (The terminal-phase regression still uses positive points only. A negative value inside the profile does not move Tlast, and there PKNCA and Caladrius agree on every parameter.) PKNCA's lin-up/log-down areas are not even numbers when a negative value is present, which is why the oracle case uses the linear rule.
- **What Caladrius does.** Under the policy `allow` (NCA-DAT-04) a negative concentration enters the areas by the linear rule, but Tlast and Clast are the last point with a concentration above zero, wherever that is: a negative value is a measurement artefact below the quantification limit, not the last quantifiable observation. For a profile that ends with a negative value this gives an earlier Tlast, a positive Clast, an area to Tlast that stops there (AUCall still reaches the last sample), and the dependent values below.
- **Why.** Clast is the base of the extrapolation `Clast/λz`; a negative Clast would give a negative extrapolated area, a negative percentage and negative volumes or an undefined logarithm in the predicted value. Taking the last positive point keeps every derived parameter meaningful. The choice follows NCA-DAT-04 and the definition of Tlast in NCA-OBS-03 (concentration above zero), and the default policy refuses negative values altogether (`NegativeConcentration`), so this only matters when a user opts into `allow`.
- **Status.** `assumed` for the Caladrius side (NCA-DAT-04 is itself `assumed`); the PKNCA side is `confirmed by oracle` by case `edge_negative_linear`.
- **Affected.** Case `edge_negative_linear`, subject 2 (the profile that ends with -0.2 at 24 h), 16 parameters: `tlast`, `clast.obs`, `clast.pred`, `auclast`, `aumclast`, `aucinf.obs`, `aucinf.pred`, `aumcinf.obs`, `aumcinf.pred`, `aucpext.obs`, `aucpext.pred`, `aumcpext.obs`, `aumcpext.pred`, `cl.obs`, `mrt.obs`, `vz.obs`. Subject 1 (a negative value inside the profile) is not affected and stays validated. Order of magnitude on the case: Tlast 24 h against 12 h, Clast -0.2 against 0.6, AUClast 32.1 against 29.7.
- **Cross-check.** The independent relations between parameters (`crates/caladrius-testkit/tests/edge_consistency.rs`) hold on the PKNCA values, so the oracle is internally sound; the difference is the definition of Tlast, not an arithmetic error on either side.
