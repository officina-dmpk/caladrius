## Goal

Step 5, third slice, from `specs/ux.md` (UX-FR-01, UX-FR-07, UX-FR-14, UX-SET-01) and the open points of T-026:

1. **Project save and load in the UI** through the existing `project.save`, `project.load`, `project.new`, `project.describe` commands: Save, Save as, Open, New in a File menu and as palette entries; the window title shows the project name and a modified marker; a dirty project asks before closing or opening another one (readable sentence, three choices); the project tree names objects from their content (UX-FR-07) and shows stale results clearly after an input change. File dialogs live in `apps/caladrius` behind `cfg` (platform code never below L3).
2. **Command palette** (UX-FR-01): one shortcut and one button open a searchable list of every registered command (id, label, one-line description from the engine schemas) plus the UI actions (new analysis from this worksheet, open analysis by name, switch theme); an entry runs the command with the current selection as context, or opens its page when parameters are needed. Test: from an open worksheet an NCA is created in at most two actions.
3. **Settings page** (UX-FR-14, UX-SET-01): one serialisable settings structure (interface language placeholder, number display: decimal mark and significant digits, default options of `nca.run` and `fit.run`, plot theme light/dark/system), searchable, each default showing its value and what it affects; the operating-system locale is only the initial suggestion and is shown as such; settings persist next to the application config (platform code in `apps/`). No setting is read from the locale without being displayed.
4. **T-026 follow-ups:** the simulation page takes its time and concentration units from the selected worksheet when there is one and says "no worksheet" otherwise; "Save as analysis" updates the simulation it came from instead of always creating a new one; the fixed duration of an infusion is a field with its unit, not a plain number; the bad-starting-value sentence is the same from `fit.evaluate` and `fit.run` (report the engine wording in the card if the fix needs the fit crate: that is an engine task, do not touch `caladrius-fit`).

Snapshots for every new screen in light and dark, looked at before delivery. All numbers still come from engine commands.
