# T-047: oracle for multiple dosing and steady state (OM-16)

- **Role:** oracle
- **State:** to review
- **Depends on:** T-046

## Goal

`specs/models.md` section 12 (T-046, MOD-MD-01..12, second source S-36 with pages) specifies superposition of n doses and the steady-state closed forms for every one- and two-compartment model with linear elimination, with lag by phase shift, the ka = k limit, accumulation ratios, Cav = D/(CL·τ), Cmax/Tmax/Cmin at steady state, and the error cases (interval shorter than the input duration, τ ≤ 0). Build the ground truth before any engine code, as T-009 and T-032 did:

1. Cases in `oracle/expected/models/md/` for the twelve models (pk1 and pk2, all routes, with and without lag): single profile under n doses (n = 1, 3, 10, 40, with regular and irregular dosing times and varying dose amounts for superposition), and the steady-state profile for interval τ (several τ including the boundary τ = T for zero-order and infusion, and τ just above tlag + T for the lag forms); expected concentrations from the versioned R script with the 256-bit evaluation (sum of the single-dose closed forms, Rmpfr) and an ODE cross-check (deSolve, dosing events) on every case; the derived quantities (accumulation ratio, Cav,ss, Cmax,ss, Tmax,ss, Cmin,ss) and the error cases as not-available rows with reasons. Record the versions; byte-for-byte reproducibility.
2. The two convention points of OM-17 that affect numbers (the steady-state lag forms needing τ ≥ tlag (+ T) and the strict versus non-strict inequalities): make them explicit cases so that the engine's choice (ours) is tested, and record S-36's printed form as a documented difference only if an engine value would differ from it.
3. Tests that fail first in `crates/caladrius-models/tests/` (same style as `oracle_models_2c.rs`), red with "unknown model" or "unsupported dosing" until the engine card lands; report the counts. Tolerances: the existing `MODEL_VALUES` constant; nothing new unless stricter.
4. `cargo xtask conformance` should list the new directory; if xtask needs a change, say so in the card for an interface follow-up rather than editing it.

## Allowed files

`oracle/`, `crates/caladrius-testkit/`, `crates/caladrius-models/tests/`, `docs/conformance.md` (regenerated), the card. Not `caladrius-models/src`, not `xtask`, not `specs/` (questions for the reader in the card thread).
