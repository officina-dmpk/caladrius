# T-020: caladrius-project and caladrius-engine: data model and command registry

- **Role:** interface
- **State:** done
- **Depends on:** T-011b

## Goal

L1 `caladrius-project`: pure serde data: a project with worksheets (columns: time, concentration, optional subject/dose/route, units as data), analysis objects (NCA, model fit, simulation) holding their options and their results, and stale marking after an input change (golden rule 5 and section 7 friction 7). L2 `caladrius-engine`: the command registry (golden rule 4): each command has a stable id (`data.import`, `data.describe`, `nca.run`, `model.simulate`, `fit.run`, `fit.initial_estimates`, `project.save/load`, `export.table`), a JSON schema for its parameters derived from the serde types (use `schemars` or hand-written schema; must be the same schema later served by the MCP server), a `describe()` listing all commands, an `execute(id, json) -> Result<json, error>` dispatch, and an append-only history of executed commands. Everything drivable without a window and serializable; no egui.

## Allowed files

`crates/caladrius-project/`, `crates/caladrius-engine/`, `Cargo.toml` (workspace deps), `Cargo.lock`, `xtask/src/layers.rs` (only if a new crate is registered).

## Completion criterion

```sh
cargo test -p caladrius-project -p caladrius-engine        # tests: schema round-trips, every command dispatches, stale marking, history append-only
cargo clippy -p caladrius-project -p caladrius-engine --all-targets -- -D warnings
cargo xtask layers && cargo xtask wasm                       # L1/L2 compile for wasm (no file IO in L1/L2: import takes bytes, save returns bytes)
```

Then `reviewer` approval.
