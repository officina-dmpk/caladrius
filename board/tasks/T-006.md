# T-006: xtask conformance hardening

- **Role:** interface
- **State:** to review
- **Depends on:** T-004c

## Goal

Make the conformance gate trustworthy (review findings on b76dc8b, see Thread of `board/tasks/T-004c.md`): a floor per parameter per case plus the expected row count; a malformed floor line or a non-empty previous file with no floors is an error; a parameter counts as validated only if the engine computed it (`r.parameter(name).is_some()`), not when both sides are "not available"; the file is written atomically (temp file then rename). Floors can only go up; the gate fails and leaves the file unchanged otherwise.

## Allowed files

`xtask/src/conformance.rs`, `xtask/src/main.rs` (registration only), `xtask/Cargo.toml`, `docs/conformance.md` (regenerated), `README.md` (append a "Conformance" paragraph only).

## Completion criterion

```sh
cargo test -p xtask                                          # new tests for each rule above
cargo clippy -p xtask --all-targets -- -D warnings
cargo xtask conformance                                      # 1312/1312, docs/conformance.md regenerated with per-parameter floors
cargo xtask conformance                                      # second run: byte-identical file
```

## Thread

- 2026-10-08 orchestrator: card created.
- 2026-10-08 interface: implemented in `xtask/src/conformance.rs`, `README.md` (Conformance paragraph), `docs/conformance.md` regenerated; `main.rs` and `Cargo.toml` needed no change.
  - Finding 1: `parse_floors` returns an error for a line starting `<!-- floor ` that does not parse (missing `-->`, wrong field count, non-numeric, validated > expected, duplicate) and for a non-empty previous file with no floor line.
  - Finding 2: floors are now `<!-- floor <case> <parameter> <validated> <expected> -->`. The gate fails if a parameter validates fewer values, has fewer expected rows, has more unvalidated rows than the floor allowed, or disappeared (case or parameter). The first-format line `<!-- floor <case> <total> -->` is still read and enforced once (migration), then replaced by the per-parameter lines on the first rewrite.
  - Finding 3: `row_validated`: a not-available expectation matches only if `r.parameter(name).is_some()` and the value is not available; a refused subject validates nothing.
  - Finding 4: `write_atomic` writes `conformance.md.tmp` then renames; `update_file` runs read, parse, check, render, write so any error leaves the file untouched.
  - Tests (xtask 41/41): floors read back per parameter, floors only go up, lost parameter hidden by gain elsewhere, new unvalidated / lost rows, malformed lines, non-empty file without floors, first-format totals, not-available rule, atomic write, failing gate leaves the file unchanged.
