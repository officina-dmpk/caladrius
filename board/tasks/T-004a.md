# T-004a: caladrius-nca: input types, validation errors, AUC rules, observed parameters

- **Role:** engine
- **State:** todo
- **Depends on:** T-002, T-003

## Goal

The public API of `caladrius_nca` as assumed by the oracle tests (see `board/tasks/T-003.md`, section "API", and the header of `crates/caladrius-nca/tests/oracle_public.rs`): `run(&NcaInput) -> Result<NcaResult, NcaError>` with `NcaInput { time, conc, dose, route: Route, options: NcaOptions }`, `AucMethod { Linear, LinUpLogDown }`, `LambdaZOptions`, `NcaResult::get(&str) -> Option<f64>` keyed by PKNCA parameter names. In this card: the types, input validation with readable errors, the AUC and AUMC integration rules over the observed range (AUClast, AUMClast, both AUC methods), and the observed parameters Cmax, Tmax, Tlast, Clast, Tfirst (first positive concentration). λz and everything derived from it come in T-004b/c; until then `get` returns `None` for those names.

## Allowed files

`crates/caladrius-nca/src/`, `crates/caladrius-nca/Cargo.toml`.

## Specification

Follow `specs/nca.md` (rules for the trapezoids, zero and BLQ concentrations, missing values, duplicated or unsorted times). Every invalid input listed in golden rule 6 returns a variant of `NcaError` with a message saying what to fix, and has a regression test in `src/` unit tests or a new `tests/validation.rs`. No `f64` indexing on input-derived vectors without bounds-checked access. The AUC method and λz options are read from `NcaOptions`, never hard-coded.

## Completion criterion

```sh
cargo test -p caladrius-nca                                   # compiles; oracle tests for AUClast/AUMClast/Cmax/Tmax/Tlast/Clast/Tfirst green, λz-dependent tests may still fail
cargo clippy -p caladrius-nca --all-targets -- -D warnings    # ok
cargo xtask layers                                            # ok
```

Report which oracle parameters are green per case. Then `reviewer` approval.
