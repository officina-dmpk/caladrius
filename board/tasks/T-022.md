- **Role:** interface
- **State:** to review
- **Depends on:** T-020

## Goal

`apps/caladrius-mcp`: an MCP server over stdio (JSON-RPC 2.0, MCP `initialize`, `tools/list`, `tools/call`) exposing every registry command as a tool with the registry's JSON schema, results returned as JSON text content, errors as tool errors with the readable message; no network; no paid dependency (a small hand-written JSON-RPC loop is fine; if an MCP crate under MIT/Apache exists and is light, it may be used, listed in ATTRIBUTION.md). An integration test speaks the protocol to the binary (initialize, list, call nca.run on theoph) and checks the result against the oracle.

## Allowed files

`apps/caladrius-mcp/`, `Cargo.toml`, `Cargo.lock`, `ATTRIBUTION.md` (append), `README.md` (MCP section only).

## Completion criterion

`cargo test -p caladrius-mcp`; clippy; a README example showing how an agent host (Pi Durable, dsh or Claude Code) registers the server. Reviewer approval; then step 4 is reached.

Deny lints present; no new dependency; no clean-room issue. Findings, most severe first:
  1. `apps/caladrius-mcp/src/lib.rs` `serve`: `read_until(b'\n', ...)` has no limit, so a client (or a bug) that sends gigabytes without a newline makes the server allocate until the process aborts; the same holds for one huge JSON array. Fix: read through `Read::take(MAX_LINE + 1)` (for example 64 MiB), and on overflow answer -32600/-32700 "line too long", discard up to the next newline and carry on.
  2. `handle_line` batches: no limit on the number of items; each item is answered and kept in memory, so `[ {tools/list} x 1e6 ]` produces a response orders of magnitude larger than the request. Fix: refuse a batch above a fixed size (for example 100) with -32600, or stream the answers.
  3. `handle_message`: a notification with a wrong `jsonrpc` value or a bad `id` type gets an error response; a message without `id` must never be answered (JSON-RPC 2.0). Fix: decide notification-ness (no `id` key) before the `jsonrpc`/shape checks and stay silent.
  4. Minor: a long fit blocks the loop, so `ping` and cancellation notifications are not served meanwhile (note it in the README, as there are no progress notifications); `tools/call` argument errors are `isError` results rather than -32602, which MCP allows; a leading BOM on the first line is a parse error.
