## Goal

Make the T-047 oracle green: `crates/caladrius-models/tests/oracle_models_md.rs` (881 tests, 880 red with "unsupported dosing") against `oracle/expected/models/md/` (246 value cases, 16,878 values at `MODEL_VALUES`; 41 refusals in `model_md_errors`), following `specs/models.md` section 12 (MOD-MD-01..12) and the T-047 card thread (its questions for the reader are answered below by the orchestrator so that you can proceed).

1. **A regimen type as data** (golden rule 5): `ModelInput` gains a dosing regimen: either a schedule (a list of doses with time, amount and, for infusion and zero-order input, duration; unsorted records accepted and sorted; a zero amount accepted) or a steady state (interval τ, dose D, duration where relevant). Single dose stays the default and keeps every existing result bit for bit (the 2c and 1c oracle tests must stay green). The provisional encoding of the oracle test (`tau`, `n_doses`, `dose_time[i]`, `dose_amount[i]`, `dose_dur[i]` in `params`) is replaced by the proper type: change the test's single helper `input_of` accordingly (that helper is yours to edit; nothing else in the oracle test or expected files).
2. **Superposition** for a schedule: the sum of the single-dose closed forms (the stable kernels of 1c and 2c), overlapping infusions allowed; concentrations and AUC(0,t) as series; derived quantities as the oracle names them (`accum_c`...).
3. **Steady state**: the closed forms of MOD-MD-03..10 per model (geometric sums), the ka = k limit, lag by phase shift, τ = T accepted, with `cmax_ss`, `tmax_ss` (bracketed bisection as for the single-dose Tmax), `cmin_ss`, `cav_ss`, `auc_tau_ss`, `accum_cmax`, `accum_auc`, `accum_c`; not-available with the oracle's reasons where it says so (tie at τ = T, tlag ≥ τ for `accum_auc`, Tmax,ss = 0 when tlag + T is a multiple of τ).
4. **Refusals** exactly as `model_md_errors` expects (τ ≤ 0, interval shorter than the input duration where the spec refuses it, non-finite or negative amounts, empty schedule...), readable, never a panic.
5. **Derivatives**: not required for regimens in this card (the fit on multiple-dose data is a later card); `Derivatives::Analytic` on a regimen input returns the readable "unavailable" error, with a test.
6. **xtask**: `conformance/step3.rs` lists `md/` through the testkit loaders (`list_md_cases`, `load_md_case`, `load_md_errors`), maps the new quantities, keeps the floors monotone; `docs/conformance.md` regenerated; `cargo test -p xtask` green.
7. Engine schema (`caladrius-engine`): expose the regimen in `model.simulate` only if it is a few lines (MCP tools/list growth under 400 bytes); otherwise leave it to an interface card and say so.

Orchestrator's answers to the T-047 questions (the reader will sync the spec afterwards, T-050): `tmax_ss` at τ = T is a tie → not available with the oracle's reason; when tlag + T is a multiple of τ, Tmax,ss = 0 as the oracle has it; `accum_auc` undefined for tlag ≥ τ → not available; P2's printed digits are the reader's rounding, the true root wins; the extra oracle quantities (`accum_c`, steady-state `auc`, times since the first dose) are adopted; τ < T is accepted for regular regimens as MOD-MD-01 says; non-integer `n_doses` is refused.
