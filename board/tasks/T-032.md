# T-032: oracle for the two-compartment models (closed-form grids, ODE cross-checks, derivatives, failing tests)

- **Role:** oracle
- **State:** done
- **Depends on:** T-031

## Goal

Step 7, second item: the ground truth for `specs/models.md` section 11 (MOD-2C-01..24), before any engine code, as T-009 did for one compartment. Follow the open items OM-06 (grids and 256-bit evaluation), OM-07 (edge and error cases), OM-10 (derivatives) and OM-11 (worked examples N1-N8, H11-H14) of that section.

1. **Cases** in `oracle/expected/models/` for `pk2.iv_bolus`, `pk2.iv_infusion` (during and after, fixed duration), `pk2.oral_1`, `pk2.oral_1_lag`, `pk2.oral_0` (and `pk2.oral_0_lag` if the spec defines it): parameter grids covering ordinary, flip-flop-like (ka near α and near β), near-degenerate (α ≈ β) and extreme ranges, times from 0 to many β half-lives; expected concentrations from the versioned R script with an independent 256-bit evaluation (Rmpfr) and an ODE cross-check (deSolve) on every case, plus the conversions between the three parameterisations (both directions) and the derived quantities (half-lives, AUC, AUMC, MRT, Vss, Vz, Cmax/Tmax where defined). Record R and package versions in each options file; fixed seeds if anything is random.
2. **Derivatives**: expected partial derivatives on a grid for the default parameterisation (cl, vc, q, vp) and the chain rule to the others, from the 256-bit central differences (OM-10), so that the future `caladrius-fit` closed forms have an oracle like T-030's grid test.
3. **Error cases** (OM-07): what the engine must refuse (α = β exactly? non-positive parameters, ka equal to an exponent handled by the limit form, overflow), as expected `not available` entries with a reason, consistent with MOD-GEN-04.
4. **Tests that fail first** in the engine test suite (`crates/caladrius-models/tests/` oracle module, same style as T-009): they fail today with "unknown model" and must stay red until the engine card lands; report the counts. Tolerances: the existing `caladrius-testkit` constants for models (never loosened); if a new constant is needed for derivatives, it must be at least as strict as the existing ones.
5. `cargo xtask conformance`: the new cases appear (0 validated until the engine exists); the xtask guard counts may need a card for the interface agent, say so rather than editing xtask.

## Allowed files

`oracle/` (scripts, data, expected), `crates/caladrius-testkit/`, `crates/caladrius-models/tests/`, `docs/conformance.md` (regenerated), the card. Not `caladrius-models/src`, not `xtask`, not `specs/` (write questions for the reader in the card thread).
