## Findings, most severe first

1. **`--strict` can never pass.** xtask/src/review.rs `claims_checked` (the `else` branch near the end of the function, ~l.560) emits a *Note* "pk1: 21 cases and 886 values, the two files agree" when the claim is correct. A confirmation counted as a note makes `--strict` exit 1 on a perfectly consistent tree (after PR #1 it prints two such notes on main, plus the drift note). The PR body and card describe this note as drift ("pk2 invisible"), which is not what it prints. Fix: emit nothing (or print it as `ok`, not counted) on agreement; keep a Note only for "README states no model counts".
2. **The motivating drift is not caught.** README.md:40 on the branch still says "two-compartment ... not implemented" in the Not-validated cell and the status line (README.md:5) still says "NCA, one-compartment models ..."; the rules only compare numbers. A README that has no pk2 row never fails (`claims_checked` only checks the rows it finds). Fix (follow-up): if the registry holds `pk2.*` ids, fail when the README has no two-compartment row or still contains "two-compartment ... (not implemented)".
3. **Tests do not back the "every rule has a positive and a negative fixture" claim.** `release_drift` has no test at all (git is shelled out); `conformance_total` has no test for the missing-file, missing-overall-line and "two halves differ" paths; `claims_checked` has no test for "no pk2 case in conformance" or "README names the file but states no counts"; `model_ids` has no empty-registry test. `the_input_to_refuse_row_is_not_a_model_id` (review.rs, ~l.845) copies the filter chain instead of calling `model_ids`, so it cannot fail if the real code changes. Fix: call `model_ids` with the refuse row in the fixture and assert no finding; add the missing paths; test `release_drift` by splitting the git call from the pure part (diff list -> finding).
4. **Golden rule 6: OK in substance, one style gap.** No `unwrap/expect/panic`, no unsafe in non-test code; the deny header is present in xtask. Direct indexing `row[1]`, `row[4]`, `row[2..6]` (readme_claims, coverage, specs_counts) is each guarded by a preceding `row.len() < N` check, so it cannot panic, but it is exactly the `[i]` on input-derived data that rule 6 forbids; use `row.get(i)`. I fed garbage (empty conformance.md, binary-ish lines, `|||||`, empty README, 23-digit numbers, CRLF, truncated table row): no panic, always a readable fail or note, but a garbage conformance.md cascades into one `review-model-ids` failure per model (noise, not a crash).
5. **Git/network/Windows/CI: sane.** `release_drift` runs `git describe --tags --abbrev=0` and `git diff --name-only <tag> --` via `git -C root`; a failure gives `None` -> a Note ("no tag found") or no finding. On the default `actions/checkout@v4` (depth 1, no tags) I reproduced `fatal: No names found` rc=128: handled, a note, never a failure. No network. Works on Windows (ran there; `load_tree` already depends on git). Caveats: `describe` picks the nearest tag, any tag (not only `v*`); the diff includes uncommitted changes locally. Cosmetic: the doc comment and the "nothing changed" message say `oracle/` but only `oracle/scripts/` and `oracle/README.md` are counted.
6. **CI placement is fine and non-blocking for notes.** `.github/workflows/ci.yml` runs `cargo xtask review` after `lint`, before `wasm`; only Fail rules (and `--strict`) exit 1. Failures do block: the rules are strict between `model.rs` string literals, `docs/conformance.md` and README counts, so a PR that adds a model before regenerating the table goes red (intended). `registry_ids` scans every non-comment string literal starting `"pk1.`/`"pk2.` of model.rs, including any in `#[cfg(test)]`, and ignores a future `pk3.`; acceptable, document it.
7. **Minor.** Finding line numbers are hard-coded (`conformance_total` reports line 1 although the Overall line is at 5; most README findings are line 0), contrary to the `file:line` promise. `versions` returns no finding when either file lacks a readable version (silent pass), and `version_in` matches the first indented `version:` anywhere in CITATION.cff (a nested `references:` entry placed before the top-level key would win). `review-specs-counts` message says `**Status:**` while the code accepts `- Status:`.
8. **Clean room / forbidden names:** none in review.rs or the card (grep for the three forbidden names: empty). Nothing from `private/`. Performance: 0.24-0.34 s on 749 files, under the 2 s budget. PR scope also touches `xtask/src/lint/mod.rs` (`load_tree` made `pub`, one word): fine.
